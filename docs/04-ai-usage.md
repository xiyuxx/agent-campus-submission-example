# AI 辅助、个人贡献与验证

本项目使用Codex辅助调研、设计、编码、测试、真实模型评估和文档整理；业务模型为DeepSeek。不能把AI编写的代码、AI执行的命令或自动生成的报告记为本人手工实现和独立执行。

2026-11-01按用户要求读取本项目5个既有聊天的全部47轮记录，加上当前聊天共6个。核查的是用户消息和执行/交付事实；本文只保留与项目有关的贡献摘要，不提交原始对话、完整试卷、私密上下文、密钥或内部推理。

## AI实际完成的范围

- 调研与设计：选题比较、公开竞品资料、需求矩阵、架构、JSON契约、SQLite表/索引/事务与运行规范。
- 编码：数据契约、Repository、四类工具、确认服务、原生循环、模型适配、业务投影、CLI、预算与故障处理、离线Mock。
- 测试与改进：构造并执行正常/缺资料/风险/冲突/重复/失败及对抗场景；修复审核失效、模型响应结构、未知值合并，验证动态工具、偏好和抢槽恢复。旧失败及修复见第18、20、21、22号文档。
- 真实模型：既有归档包含正常和受控抢槽路径；提示4.0曾出现无依据补查，4.1收紧补查后复核。每轮结果分开保留，不宣称总体质量提升。
- 本轮：修复旧协议证据检查器，新增4个篡改反例，生成15次离线业务运行，360项最终回归，重新验证干净安装，统一五份交付文档与证据索引。格式整理了3个既有检查脚本，未改变其钩子规则，未绕过钩子。

验证命令与结果见 [评估](03-evaluation.md) 和 [本轮证据](../examples/submission_audit_20261101/README.md)。本轮业务模型调用0；GitHub凭据用于用户授权的连通性/目标仓库检查和Git推送，通过忽略目录的askpass读取；未输出、提交或写入命令与remote URL。

## 记录边界

聊天历史证明的是提问、需求修正和决策过程，不能替代个人工时或手工贡献证明。用户允许按聊天记录估算为约4–5小时的AI辅助交互执行（含运行与等待），人工净工时未单独计时，后续本人试用尚未发生，详见 [时间说明](05-retrospective.md#时间记录)。先前各阶段的详细AI使用记录保留在Git历史；本文整合为当前交付口径，不把早期“未实现”状态当成当前结论。
