# 发布任务与操作入口契约

本轮经用户授权实施；硬验收优先，产品优化不代替模型决策或运行证据。本文件覆盖早期文档中“显式再次发布”、拒绝后只能新请求及无法取消的设计。

## 业务不变量

- 同素材 ID、平台、账号只有一个稳定发布任务；素材版本不构成新任务。重复操作复用，时间和内容变更属于原任务的修订。旧 new_publication 字段保留输入兼容性，但不授予绕过防重复的权限。
- 任务、不可变请求、草稿修订分离。用户显式修改要求才生成新的内部请求；模型没有修改硬要求、创建独立重复任务、取消或代签确认的权限。
- 原要求已过去，但已确认的未来草稿仍有效时，可以复用该草稿；不因此自动授权其他改期。候选在保存前过期，模型可在原授权候选范围和预算内重新查询，新的偏离仍待确认。
- 历史确认回执与当前有效性分别返回。查询、确认重放、工作清单和导出均重新检查当前方案，过期或依据变化不能显示可交接。
- 同任务新方案成功保存时，旧方案退出当前状态、新方案和任务指针在同一 SQLite 事务提交。失败回滚保留原有效方案，清楚显示修改未完成；旧确认不能继承给新方案。
- 取消是明确用户操作，保留历史并释放本地容量；不意味着撤销外部发布。恢复取消任务必须显式操作。

## 存储与兼容

增加版本化迁移、唯一任务表、任务请求关联和操作事件。迁移旧草稿前检查同素材/平台/账号的多份 active 草稿，发现歧义整体拒绝，报告需处理的草稿，不静默选择或删改历史。旧 run/confirm 等命令保留；工作入口自动管理请求 ID、修订和运行目录。旧请求不能绕过任务当前版本或恢复已取消任务。

## 用户入口

CLI work 提供工作清单、开始检查/继续、修改时间、补资料、确认、取消/恢复和导出。资料补充只允许业务事实白名单并经类型校验、目录更新和重新审核。批量操作每次最多三项，沿用逐项及整体预算。保存失败可继续检查；回执不明先读取数据库核对。

工作清单显示素材、账号、要求、建议、风险、待办和保存情况；技术 ID/修订/Trace 可在详情查看。可交接仅指本地草稿有效且确认完毕。导出重新查询数据库，只导出当前要求对应、有效、已确认或无需确认的草稿，并明确没有执行真实发布。

## 验证门槛

保留全部六项业务验收、执行边界和离线测试。增加确认重放过期、已确认未来方案复用、候选到期恢复、极端日期、任务唯一性、迁移歧义、修改失败保留旧方案、旧确认不继承、取消释放时段、操作并发和导出复核。生成当前源码的正常/资料不足/工具失败等实际运行记录及至少两条真实模型路径；结果、限制和 AI 使用同步五份交付文档。分阶段本地提交；本轮不自动推送。
