## 用户与业务目标

内容团队需要审核待处理素材，识别风险、信息缺口和时段冲突，形成可由用户确认的排期草稿。
成功标准是审核依据清楚、建议可核查、硬性要求不被越权修改、同一请求不重复创建草稿、保存状态如实呈现。

## 素材的项目定义

一个素材 ID 对应单个平台、单个账号、指定内容版本的发布单元；同一成片跨渠道分别建单元。使用合成 JSON 和媒体引用，不实现视频像素理解、音轨提取或真实版权核验。审核仅对所提供资料与规则负责。

## 输入与输出

输入：素材 ID、合成元数据与补充资料、明确的发布日期与带时区的时段要求、要求是否为硬性约束、已有排期、带 ID 的审核规则、请求标识及可选的用户明确确认。
不清楚的硬性条件或确认语义需要澄清，不能由模型自行假定用户已同意。

每项素材的结构化输出至少包含：

- 审核状态：通过、信息不足、需要人工确认、阻断，附风险原因和规则 ID。
- 原始发布时间要求与独立的建议时段，包含冲突事实与替代建议理由。
- 确认状态和具体待确认项；确认只适用于明确的素材、时间和方案版本。
- 草稿保存状态：未尝试、已保存、复用、已更新、保存失败或保存结果未知，及可核查的草稿 ID。
- 整体任务状态、已完成部分和未完成原因。

审核状态、确认状态、保存状态互相独立。待确认草稿可以保存，但不能因此被说成用户已确认或占位成功。

## 最小范围

单 Agent、CLI、真实模型动作循环、本地合成资料、四类工具、有界执行、持久化草稿和完整 Trace。
首版支持少量素材逐项处理，明确单次任务中的部分成功；不承诺整批原子保存。
时段容量采用合成规则：同平台、同账号、同一精确离散时段容量为一；时间含日期和时区并统一到 UTC 比较。已有排期与其他有效草稿建议参与本地规划冲突检查。

仅保存草稿，不提供发布工具。用户硬性要求保留为原始事实，未同意的替代时段只是建议。
素材缺关键资料或命中阻断规则时，首版不创建可执行排期草稿，返回缺口或阻断依据。

## 关键业务边界

- 冲突时由模型选择补查、替代时段或请求确认。程序确定性地校验容量、确认和保存前置条件。
- 所有时间都包含日期与时区；不把单独的“18:00”当作足够的绝对排期时间。
- 身份和版本字段由契约校验；可缺失业务事实由导入规则确定必填性，不因出现在示例中而自动必填。默认合成规则检查版权缺失、明确未授权、封面缺失及指定风险文案，默认不要求 license_ref 必填；详细字段和规则契约见开发实现参考第 4 章。
- 原时间独立检查；显式候选无需属于默认 allowed_slots，可包含用户明确列出的跨日时间。候选省略/null 才采用请求时区同日默认候选，[] 表示没有替代空间，不自动扩大范围。
- 硬性时段不可直接替换。用户通过后续明确输入确认具体替代方案后，才可进入已确认状态。
- soft 也不授权自动改期；所有偏离原时刻的建议都需确认。无可用时段时返回 needs_input、无建议时段，明确请求调整范围；尚未保存则为 not_attempted，此前保存遭到冲突拒绝则保留真实操作状态；有可保存方案时先保存待确认草稿，再请求确认。
- 同一 request_id + material_id 只产生一份草稿，不把建议时间放进唯一键。每次执行重新检查；结果不变复用，方案变化更新同一草稿修订。原始输入摘要不同则返回冲突，修改原始需求使用新请求标识。
- 查询、旧方案核查、保存和确认均排除当前逻辑请求的草稿自身；同素材在其他请求下的有效草稿仍参与占用。items 顺序不表达优先级，规范摘要与逐项执行均按 material_id 排序。
- 更新资料或已有排期后，可使用原请求重评估；补齐原请求中的空时间等字段或改变候选范围属于改变原始输入，使用新请求 ID。新请求独立处理，不自动替代或撤销旧草稿。
- 用户确认独立绑定 draft_id 和 revision；更新方案失效旧确认，不覆盖原始要求。CLI 接受操作者明确输入，不声称实现企业身份鉴权。
- 同语义有效草稿复用时保留当前确认。拒绝只适用于当前 active 修订的未决可确认项，拒绝任一项即拒绝整份方案；同请求重跑不能恢复已拒绝方案。首版不提供原要求就地编辑、自动替换请求或已确认方案撤回。
- 保存之前再次检查工具和资料结果；保存失败必须明确输出失败，不允许模型凭空声称有草稿 ID。
- 待确认建议仅占本地草稿规划容量，不预占真实平台正式时段。保存和确认都重新核对当前占用；旧方案失效后不继续占本地容量。
- 草稿状态和正式已发布排期分开建模；任何阶段都不得声称已经发布。

## 已确定的工程目标

数据库设计采用完整目录快照导入、草稿证据快照及独立确认/状态事件，字段与约束见 [数据库设计](15-database-design.md)。同内容导入不失效；实际目录变化首版保守地要求全部旧 active 草稿复查，rejected 不恢复。缺席资料退出当前目录，历史保留。当前仅有 DDL 结构检查，不表示以下业务验收已运行。

交付一个可运行、可测试、可审查的 Agent 项目，真实记录 AI 辅助范围与效果边界。
必须有模型根据工具观察选择后续动作的循环、受限执行、离线入口和完整运行证据。
