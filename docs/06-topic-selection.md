## 选择理由

1. 业务结果可核查。审核结论、时段占用、用户确认、草稿数量和保存结果都有明确事实依据，适合写有意义的断言。
2. 模型调整有自然触发点。缺资料可补查、时段冲突可找替代、规则风险可请求确认或停止、保存失败可重试或返回失败。
3. 工程能力有展示空间。幂等保存、确认边界、事务一致性和部分成功保留都服务具体业务，不需要额外搭建复杂系统。
4. 工具和数据边界可控。四类工具可以用合成资料与本地实现支撑，模型决策单独使用真实模型验证。
5. 三小时范围可收敛。CLI、单 Agent 和本地草稿即可完成核心，不依赖界面、部署或真实发布系统。

## 其他题目的主要成本

- 企业知识问答是次选。引用可校验，但还需要覆盖改写检索、上下文追问、冲突文档的查证与停止条件；若只靠词面匹配，容易出现演示有效而改写失效的问题。
- 内容任务规划具有很好的重规划空间，但费用口径、步骤依赖、部分成功保留和重复执行状态需要一起建模，容易扩大三小时范围。
- 短视频脚本适合展示迭代修正，但事实支撑、风格质量、分镜与时长的一致性同时影响效果；估时与文案质量的验证带有更强近似性。

## 所选题的难点与应对

- 不能退化成固定规则分支：程序提供事实与边界，补查、替代、请求确认等业务动作由真实模型选择，并保存两条以上不同观察路径。
- 不能擅自改变硬性时间：原始要求和建议分开记录；确认必须来自用户，模型不能自己生成授权。
- 不能以“已保存”暗示“已排期或发布”：审核、确认、保存分别建模，输出状态以工具结果为准。
- 不能只做内存去重：通过持久化唯一约束支持跨进程重复提交；同标识不同内容拒绝静默覆盖。
- 排期查询后可能变化：保存或确认前再次校验；待确认候选不承诺预占时段。
