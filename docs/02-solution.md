## 技术选择

Python 3.13 + argparse CLI + 原生单 Agent 工具循环 + DeepSeek Tool Calls + HTTPX + Pydantic 2 + SQLite + pytest + Ruff。
模型默认 deepseek-flash、非 thinking 模式，提供同接口离线 Mock；精确依赖在实现时解析、锁定并验证，当前未安装。

## 核心职责

- 模型选择补查、风险处理、候选查询、替代建议及结束；每次工具观察返回模型。
- 四类工具：read_material、check_rules、query_slots、save_draft。
- 程序校验参数、资料、规则、确认、预算和数据库写入；可信事实决定最终保存状态。
- 素材 ID 对应单个平台、账号、内容版本的发布单元；合成 JSON 承担业务资料，不宣称真实视频审核。
- 输出每项审核状态、风险原因、建议时段、待确认项、保存状态及整体任务状态。

## 状态与写入

原始硬性要求始终保留。可以提出替代但不得替用户同意；确认来自 CLI 用户输入，绑定具体草稿修订。
待确认草稿可以保存，正式发布不在工具能力内；关键资料缺失或命中阻断时不保存可执行排期草稿。
数据库中的待确认建议参与本地规划冲突检查，不代表已预约真实平台；保存前和确认前重新检查资料版本及占用。

唯一键为 request_id + material_id，不含建议时段。重复执行重新观察；结果不变复用草稿，方案变化则更新同一草稿修订并失效旧确认。相同请求标识但原始输入不同返回冲突。
查询与写入均排除当前草稿自身，同素材其他请求草稿仍计入占用；同方案复用保留当前有效确认，拒绝后重跑不恢复方案。更新资料后使用原请求重评估，改变原始要求使用独立新请求，不自动替代旧草稿；首版不提供已确认方案撤回。
明确保存失败与结果未知分开；未知结果先核对提交状态，不能凭超时断言未保存。

## 业务流程定稿补充

字段类型与运行身份由契约校验，业务必填性由导入规则决定；默认合成规则和补查白名单统一定义在开发实现参考第 4 章。原时间独立检查，显式候选可以跨日且无需属于默认 allowed_slots；省略/null 才使用请求时区同日默认候选，[] 不回退。候选范围不表示改期批准。

无可用时段时，根据真实查询返回 needs_input，不保存新方案；有可保存方案时先保存并将回执返回模型，再结束或请求用户确认。缺项与调整范围是输入待办，不能用“接受”解决；改期与软风险才是可确认项。以上为后续数据库开发流程设计需承载的业务行为，尚未实现或测试。
