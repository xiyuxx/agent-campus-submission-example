# 方案与技术取舍

当前实现为 Python 3.13 CLI + 原生有界单 Agent + DeepSeek Tool Calls + HTTPX + Pydantic 2 + SQLite。可执行入口见 [README](../README.md)，契约细节见 [实现参考](13-implementation-reference.md) 和后续第19、23、24号修订。

## 当前审核修复

最低完整性使用公开系统规则并写入RuleCheck与保存证据，再执行导入规则。普通运行按真实业务时间检查原要求、候选、保存和接受确认；显式回放只替换业务参考时刻，不改变真实审计时间或monotonic预算。

查询与保存事务均检查同素材版本/平台/账号的已有有效未来草稿，默认跨request_id拦截；用户输入new_publication才允许独立再次发布。标志进入不可变请求摘要，模型工具不暴露此权限。

输出版本1.1单列proposed_plan及related_drafts；持久化方案与本次未保存/未知/失效提议分别组装，保留保存错误及旧草稿事实。无数据库列变更，标志由原请求JSON持久化，最低规则定义进入历史payload。旧草稿会在复核时因新审核依据失效，需要重评估。详细定义及实际验证见 [第26号契约](26-review-remediation.md)。

## 动态决策与调用流程

CLI 校验请求、登记不可变原要求、复核旧草稿；每项建立独立上下文。agent.run_item 每轮将用户业务要求、剩余预算、当前方案、工具观察和可用工具发给模型。模型返回工具调用或结构化结束请求，程序执行真实本地工具，把观察加入消息，再调用模型。模型不是脚本化固定分支，离线 Mock 另行实现并明确标注。

四类工具为 read_material、check_rules、query_slots、save_draft。读取支持 basic/supplement，补充仅填未知且保留来源；规则检查区分 passed/needs_info/needs_review/blocked。排期工具在同一读事务检查原时间，冲突时自动检索两侧最近合法节点，模型结合观察及 nearest/prefer_before/prefer_after 偏好提出建议。

工具 Schema 按当前可信状态收窄，执行入口再次校验。阻塞缺项和可选缺项分开展示，有审核依据且有来源才开放补查。业务 ID、修订和证据关联由本地绑定，model_view 白名单只投影必要业务信息。

保存时抢槽返回 SLOT_CONFLICT 和 recovery_action=query_slots，使旧查询失效。模型消费错误后可重新查询、改选候选，最多恢复两次且仍受总预算约束。正常与抢槽真实路径见 [评估](03-evaluation.md#真实模型的两条路径)。

## 可信状态、事务和确认

程序以真实观察及数据库状态校验结束和组装输出，模型不能凭文本生成成功回执。成功保存必须先回传模型；最后一轮刚保存但未消费回执仍可返回 incomplete。

SQLite 使用短事务、外键、历史证据和唯一约束。request_id + material_id 是稳定逻辑键，建议时间不进入唯一键；同方案 reused，变化时更新同一草稿 revision 并失效旧确认。保存事务重查当前规则、依据、修订和容量，不在写事务内等待模型或外部审核。

原始要求与建议时间分开，任何改期都待用户确认；confirm/review 由操作者显式选择，绑定具体草稿修订，不让模型猜测同意。草稿保存、审核通过、用户确认和实际发布是不同状态，本项目只具备前三者的本地表示。

审核当前资格同时匹配目录版本和有效素材摘要；变化后清除旧审核，结束和结果输出再复核。明确回滚报告 failed，回执丢失用写入凭据核对；仍无法确定为 unknown/incomplete，禁止盲重试。

## 执行与资源限制

每项16次模型尝试、16次工具尝试、180秒；请求最多3项、540秒。整次模型调用最多30秒，连接5秒、读写30秒并受剩余预算约束。临时错误最多额外重试一次，协议反馈最多两次，冲突重查最多两次；重试消耗预算。还有上下文、响应、工具参数及结果体积限制。

Trace 自动记录调用参数、简短依据、工具返回和送达观察ID，run.json 记录源码摘要、模式、模型返回标识、usage、预算及退出码，不存内部思维过程、密钥或完整原始上下文。

## 选型理由与边界

CLI 易于复制运行和断言；原生循环足以清楚表达四类工具与有界消息历史，不引入框架 Runtime。HTTPX 隔离供应商传输，Pydantic 约束外部协议，SQLite 事务承担幂等、占用和修订，模型与审核器通过小接口隔离。精确版本见 requirements.lock，全新环境验证见 [安装证据](../examples/submission_audit_20261101/install-check.json)。

没有框架版本需要另行声明；pytest、Ruff 只承担测试和质量检查。业务资料可用合成数据，本地函数工具允许离线执行。外部视频审核、自然语言请求入口、长期记忆、跨进程逐步续跑、企业鉴权、真实发布均未实现；逐项排期不保证全局最优，保守目录版本可能产生额外复查。
