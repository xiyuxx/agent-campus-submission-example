# 素材审核与发布排期：流程调研

本记录区分公开资料中的通用实践与本项目的设计判断；不代表对小影内部流程的调查。调研日期：2026-10-30。

## 不使用 Agent 的常见流程

1. 建立内容计划：确定主题、受众、渠道、发布时间窗口、负责人和截止时间；内容日历维护各项任务和关键节点。
2. 素材入库：登记版本、文案、图片/视频、来源、授权、适用范围和缺失字段。
3. 审核：编辑检查事实、文案与品牌；需要时交由业务、版权或法务人员核查。风险高的内容采用更严格的审批链。
4. 排期：按渠道、日期、时区、活动约束和已有排期检查冲突；协调负责人提出备选，并取得必要确认。
5. 提交审批与排程：审批人核对具体版本及排期，修改重要内容后重新审核；经过授权的人员在发布工具中排程。
6. 发布与复盘：实际发布后核对结果与链接，记录表现和问题，更新内容或归档。

小团队可使用表格和聊天协作，大团队可能使用带权限、审批链和内容日历的系统。具体流程随团队、渠道和风险变化。内容日历记录主题、发布渠道与日期、负责人及关键流程时间：[Content Governance](https://www.cypres.com/sites/default/files/booklets/Cypres_ContentGovernance_EN_WEB.pdf)。[Hootsuite](https://blog.hootsuite.com/social-media-approval-workflow/) 描述了职责、分级审批和修改后重新送审的做法。

## 难点

- 素材、规则与授权分散，字段缺失或版本过期导致反复追问；格式完整不代表事实真实或权利齐全。
- 合规风险常取决于上下文和业务事实；存在模糊表述和规则冲突，关键词命中并不等同于违规。
- 多平台、多账号、时区、活动窗口、人工工作时间和优先级交织；同一时间能否共存取决于具体业务规则，不可假定所有同频道内容都冲突。
- 时段查询与保存间，其他人可能改变排期；排期数据若不完整，无法承诺全局无冲突。
- 谁能批准什么、审批对应哪个版本、变更是否需要重审，必须有清楚的责任和记录。
- 重复请求、保存超时及真实失败不易区分；不核对保存结果可能造成重复或虚报成功。
- 流程过重带来排队；过度简化又会漏掉高风险内容。审核深度应随具体风险、组织政策调整。

## Agent 负责什么

| 环节 | Agent 可承担 | 人和确定性系统的边界 |
| --- | --- | --- |
| 汇总待处理素材 | 读取资料、发现缺项、发起补查、整理问题 | 工具提供可信来源和版本；资料不足时不补造 |
| 风险初筛 | 根据规则检查观察解释风险，选择进一步查询或人工复核 | 明确阻断规则由程序执行；模糊、高风险事项由授权人员判定 |
| 排期建议 | 查询占用、筛选候选、按明确偏好解释建议与取舍 | 程序校验容量、日期和时区；硬性要求的改变须用户明确同意 |
| 审批准备 | 汇总具体素材版本、风险依据、原要求、候选和未决事项 | 审批必须来自授权人，且针对具体内容及方案版本 |
| 草稿保存 | 选择在满足前置条件时调用保存工具，依据结果报告状态 | 工具负责持久化、幂等和冲突复检，禁止伪造保存结果 |
| 异常处理 | 观察结果后选择补查、替代、请求输入或停止 | 超时、步数、重试由程序限制；错误必须可见 |

人机协作需要让审核人看到待审核的具体动作、依据与影响，防止只对笼统目标进行形式化批准。对高风险操作的人工干预与清晰审批流程可参考 [OWASP Agentic Applications Guide](https://genai.owasp.org/download/49059/?tmstv=1753666640)。

## 判断示例（设计，非真实 Trace）

同一素材在指定日期、频道的 18:00 硬性时段：模型读取素材和规则；若资料不全，选择补查或请求补充；若规则阻断，则结束并列明规则及证据；审核允许继续时查询时段。

若观察到 18:00 可用，模型可选择保存草稿；保存工具校验当前状态并返回真实结果。若 18:00 被占用，模型可查询附近时段；发现 19:00 可用后建议 19:00，保留原始要求并标记待用户确认。待确认草稿可以保存，但不表示 19:00 已被预占或用户已同意。用户确认具体方案后再重新检查时段并处理修订。若保存报错，报告保存失败；若状态不确定，应先查询结果再决定是否重试。

模型每轮只根据已经观察的资料和工具返回选择后续动作；程序验证工具参数、规则和授权，并给出调用上限。原始素材是数据，不是能更改系统指令的命令。

## 项目范围与可检验指标

题目限定只保存草稿，真实发布、正式平台审批、发布后回执和效果分析不实现；示例规则、渠道容量和素材均为合成设定。冲突检查只对所接入的合成排期有效，不代表企业实际全局无冲突。

评价至少包括六项必验：正常、素材缺失、规则风险、时段冲突、重复提交、保存失败。另验证确认绑定、数据更新后复查、幂等键冲突与预算耗尽。模型能力通过至少两条真实模型 Trace 比较观察变化与后续动作；Mock 仅验证流程。后续可统计每项任务完成时间、人工回退率、风险漏报及误报、冲突漏检和错误保存，但没有真实基线或样本前不声称改善幅度。
