# 公开实例：内容审核与排期

调研日期：2026-10-30。下列实例来自厂商公开的客户案例或产品操作文档，不代表小影内部工作方式。厂商案例可能具有宣传倾向。

## 实例一：Imagine Social 内容代理机构

[Agorapulse 客户案例](https://www.agorapulse.com/blog/success-stories/imagine-social-case-study/)介绍，Imagine Social 原来用 Trello 看板组织内容，并邀请客户参与；业务增长后，需要更好地协调多个平台的提前排期、共享内容和客户审批。案例描述了使用共享日历开展客户审批等方式。

这说明真实工作既包括内部制作，也包括让客户看到待发内容并提出批准或拒绝意见；日历帮助各方共同查看内容及其安排。案例没有给出本项目的具体素材、冲突或 Agent 决策，不能把参考实例当成该客户的真实记录。

## 实例二：Sprout Social 审批与发布工作流

依据 [Sprout Social 审批文档](https://support.sproutsocial.com/hc/en-us/articles/205974715-Message-Approval-Workflows)：工作人员编辑帖子，添加文案、媒体和元数据，选择审批流程并提交；审批人查看内容，可以批准或退回并提供意见。未在计划时间前完成审批的内容不会按原定时间发布，需要修改时间并重新提交。账号连接断开也可能导致后续发布失败。

该例来自真实产品的使用说明，不是公开到某条真实帖子的完整个案。它展示了“待审批”“已排期”“实际发布”等状态各有含义；本项目只保存草稿，不执行该产品的后续发布。

## 实例三：大型媒体团队的内容协调

[Airtable 客户工作流材料](https://assets.ctfassets.net/wl95ljfippl8/7HrSnhqPBxffj9qzsFN3Pw/2ba084e214c82821c45a13cd4e4d0033/7_AI_marketing_workflows_from_real_Airtable_customers.pdf)描述一家未具名媒体娱乐企业：跨 Instagram、Facebook 和 YouTube 每天协调约 20–30 条内容，原先使用 Excel、PowerPoint、WhatsApp 和邮件，面临负责人不清晰、审批状态难跟踪及大视频移动端下载失败等问题。该材料是厂商发布的案例摘要，数量和效果属于其披露内容。

这个实例体现素材、渠道、负责人和审批状态需要关联；具体业务规则、客户身份和本题中的冲突处理并未由材料证实。

## 结合题目的教学示例：非真实客户记录

假设一个品牌准备发布产品视频：运营提出发布时间 → 编辑准备成片、封面和文案 → 审核人员核对事实、授权和品牌规则 → 排期人员检查已有安排 → 如有冲突提出备选并取得确认 → 保存草稿 → 授权人员在发布系统中完成后续审批和发布 → 核对发布结果。

本项目 Agent 覆盖中间的素材读取、规则检查、时段查询及草稿保存。比如 18:00 已占用时可以建议 19:00，但必须保留原要求并标记待确认。后续审批与实际发布是业务背景，不由该项目执行。草稿保存后仍可能需要修改素材、人工审核或确认替代时段。

应当区分真实案例记载、产品文档所展示的功能、以及以上用于解释的虚构业务示例；不能把教学示例写成真实客户的执行记录。
