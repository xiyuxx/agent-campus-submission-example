状态：2026-10-31，用户已确认的变更契约；实现与验证结果另记于阶段记录。本文取代 docs/13、docs/17 中“模型填写身份/观察 ID/修订”“默认候选限同日”“返回全部候选”的旧约定；其他预算、规则、确认、事务和幂等语义继续有效。设计示例不是实际运行证据。

实际实现提交为 410ae2b。新协议实际示例见 [运行索引](../examples/local_binding_nearest_v2/README.md)：6 组 Mock、2 组 live；完整离线回归 138 passed、1 xfailed（已有 ADV-01）。运行、类型/关联核查及数据库交叉检查分别保留，不把协议投影重建检查等同于原始 HTTP 报文归档。

## 1. 用户输入与本地身份

普通用户只需提供当前素材和原发布时间要求，不必为每次请求提供候选时间。运营人员事先按平台、账号导入带日期与时区的 allowed_slots。它是已配置的有限节点集合，不是无限生成的日历。

request_id、material_id、account_id、draft_id、revision、observation_id、rule_id、source_id、导入 ID 和内容摘要留在本地数据库、上下文与证据中。程序校验后把模型业务动作与这些本地事实绑定，不能把模型返回当作可信事实直接拼接入库。

模型看到当前项的原时间、时区、hard/soft、业务资料、风险说明、可用时间和保存/确认状态。工具 Schema、起始消息、工具观察正文、结束对象不要求或注入内部业务标识与修订。API 的 tool_call_id/响应关联号由协议层保留，不用于业务判重。

## 2. 双向最近节点

原时间单独精确查询，即使它不在预设节点中也允许检查。原时间空闲时可保存原方案；冲突后由模型选择 nearest 查询，不由程序偷偷补做业务链路。

nearest 在同平台、同账号的合法节点范围中，按 UTC 绝对时刻分别检查：

1. 原时间之前的节点按时间倒序，取第一个可用节点。
2. 原时间之后的节点按时间正序，取第一个可用节点。
3. 两边都有就返回两个，一边有就返回一个，两边没有就返回空集合。

同一时刻的等价时区表示去重；原时间自身不属于替代节点；两侧等距时两个都返回。可以跨日期，不按请求时区的当天截断，不按现实“现在”额外过滤历史合成日期。没有接入的禁发、周期生成或全局最优规则不自行推断。

candidate_times 作为旧输入兼容限制保留：省略/null 使用全部已配置节点；显式非空数组只在该数组内找两侧最近可用；[] 没有替代空间，不回退。旧请求的规范摘要不改，改变原始请求仍需新 request_id。

例如原要求 18:00，17:30/18:30 已占用，17:00/19:00 空闲，返回 17:00 和 19:00。不是只往后查，也不是全局取距离最小的两个（它们可能在同一侧）。

## 3. 模型工具契约 v2

| 工具 | 模型参数 | 本地注入 |
| --- | --- | --- |
| read_material | detail=basic/supplement，reason_summary 可选 | 当前素材与目录身份 |
| check_rules | reason_summary 可选 | 当前有效素材快照 |
| query_slots | query=requested/nearest，reason_summary 可选 | 当前请求、平台账号与合法节点范围 |
| save_draft | suggested_at，reason_summary 可选 | 已回传审核/时段证据、请求身份和本轮绑定修订 |

未知参数仍拒绝；模型不能借额外 material_id、expected_revision、观察 ID、确认字段或发布字段改变作用域。FinalProposal 仅 action=finish/needs_input/block 和 reason_summary，不再有 evidence_ids。本地最终结果和 Trace 仍保留完整证据引用，不改变用户结果 schema_version=1.0。

## 4. 模型可见观察与本地真实观察

本地 ToolResult 保持完整 observation_id、catalog_revision、事实来源和真实业务对象；新增白名单投影生成模型观察：tool、ok、code、retryable、业务 data。二者不混用。

素材投影显示标题、类型、文案、版权状态及媒体/封面/授权资料是否提供；不发送素材/账号身份、资源 URI 或授权登记编号。规则投影显示实际命中的字段、风险级别和说明，不发送规则/来源 ID 或完整内部快照。时段投影显示带偏移的时间、方向、可用性和冲突来源类别，不发送占用记录 ID。保存投影显示真实保存结果、有效性、建议时间、确认状态和可理解的待办说明，不发送草稿 ID/修订和待办内部 ID。

白名单排除结构化内部元数据，不改写用户业务文案或声称能够识别任意自然语言中的全部标识。Trace 中保存脱敏模型动作及其本地关联，不能将完整内部 ToolResult直接作为模型输入。

## 5. 观察送达、本轮修订与保存

只有实际工具产生、且已在后续有效模型请求中回传的观察能用于模型保存动作。新资料使旧审核失效；两侧查询与原时间观察都留在本地。保存时程序按 suggested_at 匹配本轮最新、已回传且有效的查询，不由模型指定观察引用。

每次模型请求前记录当前本地已知草稿修订。该响应的保存动作使用这一绑定版本，不能在写入前偷偷换成数据库最新修订。修订冲突返回可理解的“当前方案已变化，请重新评估”，本地刷新草稿状态，下一次模型请求展示不含 ID 的新方案摘要；不靠模型猜数字恢复，不自动覆盖其他运行。

一次模型响应内可以依次读取和检查，但不能保存尚未回传的检查/时段结果。数据库事务仍核对真实资料、版本、规则、候选范围和当前占用；查询时可用不保证提交时可用。保存抢槽后由模型再次查询，不自动选另一个时间保存。

保存回执本地绑定 draft_id、revision、目录版本、语义摘要。结束前核对当前版本与已消费回执一致；其他运行修订方案时，旧回执不能证明当前方案已由本轮处理。无法核实提交仍为 unknown/incomplete，非法后续调用不能把 unknown 改成确定失败。

## 6. 选择、确认与持久化

查询返回最多两个方案，模型可在已有业务偏好下推荐其中一个；无其他偏好时可说明按距离选择，等距可推荐任一但不能称用户已接受。Mock 以距离优先、等距后一个优先作为显式工程策略，不宣称这是用户授权或真实模型表现。

只保存模型选定的一份建议草稿；两个候选不创建两份草稿、不各占一个容量。原 hard/soft 要求不改，任何往前、往后或跨日的改期都产生 change_time 待确认项。确认来自独立 confirm/review，绑定当前精确修订，不经模型代签。

本地快照保留本轮已发生的原时段查询、nearest 两侧结果、查过的占用证据和保存复核。保存事务复核节点仍属于当前合法集合且实际可用；不把原时段查询未执行的事实补写进历史。现有单个 slot_observation 保留兼容，新证据集合补充实际观察。

## 7. 必须验证

- 普通请求省略候选，能够从预设节点找到前一个与后一个空闲时间。
- 连续占用被跳过；某一侧没有空闲只返回另一侧；全部占用返回空；等距返回两侧。
- 前一天和后一天节点可查；只比较同平台账号，UTC 等价去重，原时刻不制造假改期。
- 显式候选限制与 [] 保留；保存不能越过本轮返回的最多两个建议。
- 真实 HTTP MockTransport 捕获的每轮业务消息、工具 Schema 和回执没有程序注入的内部 ID/修订；协议 call_id 配对完整。
- 保存只使用已回传有效依据；同响应猜测证据、额外字段或伪造身份不能保存。
- 保存前抢槽、目录变化、修订冲突、旧回执对应新修订均有明确拒绝/未完成，不覆盖并发变化。
- 同请求重跑一份草稿，同方案复用保留确认；改期、软风险、拒绝和 unknown 的边界不变。
- 生成新的实际离线运行示例，旧 live 记录保留其旧源码版本，不能冒充新协议已通过。
