# 复盘、学习与下一步

项目已实现素材审核与排期草稿的本地CLI闭环。本轮修正的是交付一致性：核心代码已有356项测试，README却仍写71项，五份文档混有早期“未实现”，旧证据检查器无法处理当前归档和合并查询协议。修复检查器、补4项篡改反例并重新执行后，最终360项通过，当前评审入口统一见 [README](../README.md)。

## 难点与学到的内容

最难的是让审核、建议、用户确认、保存回执和当前事实保持一致。旧审核通过不代表新规则仍通过；保存成功不等于用户已确认；回执超时不等于没有写入。实际改进将审核绑定目录版本及素材摘要，保存事务独立复核，并用内部写入凭据核对不确定结果，确认绑定具体草稿修订。

用户对“ID为何交给模型”和“替代节点为何再让模型查一次”的追问促成职责调整：身份/修订/证据留本地，确定性的原时间检查和双向候选检索合并为一次工具观察，模型消费业务事实后推荐或恢复。对当前小型规则集，不声称模型不可替代；真实工具循环和两条live证明它确实消费观察调整动作，是否值得额外成本还需更多业务样本。

反例测试比只验证正常链路更能发现问题。规则只变、素材不变暴露审核失效；一次message=null暴露响应结构边界；补充title=null暴露未知值语义。128个占用组合用独立oracle求最近前驱/后继，避免用实现验证自身。发现xfail后单独核实与修复，历史失败不改写成通过。

## 已知不足与下一步

当前样本为合成资料，元数据规则不能证明视频理解或真实版权判断；live每条仅一次，未测稳定成功率。没有强杀/断电恢复、长期并发、大规模性能、企业身份鉴权或真实发布。没有整批最优排期、通用撤回或自然语言入口。

优先补多轮独立live样本和更丰富风险资料，继续核对工具观察、恢复动作及调用成本；若接外部审核，先约定素材版本绑定和异步报告，避免在写事务等待网络。正式题号仍待核实，实际人工用时缺少独立计时。用户随后明确授权提交推送；原22次历史已推送到公开仓库，本轮交付修正随新提交上传，最终远程SHA在操作完成后核对。
