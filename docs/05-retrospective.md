# 复盘、学习与下一步

当前运营体验和任务工作流的补充复盘见末节；下面早期392/360项、显式再次发布和无法取消等文字保留历史语境，当前结果以 [评估](03-evaluation.md) 与 [第28号契约](28-operator-experience.md) 为准。

项目已实现素材审核与排期草稿的本地CLI闭环。本轮修正的是交付一致性：核心代码已有356项测试，README却仍写71项，五份文档混有早期“未实现”，旧证据检查器无法处理当前归档和合并查询协议。修复检查器、补4项篡改反例并重新执行后，最终360项通过，当前评审入口统一见 [README](../README.md)。

## 难点与学到的内容

最难的是让审核、建议、用户确认、保存回执和当前事实保持一致。旧审核通过不代表新规则仍通过；保存成功不等于用户已确认；回执超时不等于没有写入。实际改进将审核绑定目录版本及素材摘要，保存事务独立复核，并用内部写入凭据核对不确定结果，确认绑定具体草稿修订。

用户对“ID为何交给模型”和“替代节点为何再让模型查一次”的追问促成职责调整：身份/修订/证据留本地，确定性的原时间检查和双向候选检索合并为一次工具观察，模型消费业务事实后推荐或恢复。对当前小型规则集，不声称模型不可替代；真实工具循环和两条live证明它确实消费观察调整动作，是否值得额外成本还需更多业务样本。

反例测试比只验证正常链路更能发现问题。规则只变、素材不变暴露审核失效；一次message=null暴露响应结构边界；补充title=null暴露未知值语义。128个占用组合用独立oracle求最近前驱/后继，避免用实现验证自身。发现xfail后单独核实与修复，历史失败不改写成通过。

## 已知不足与下一步

当前样本为合成资料，元数据规则不能证明视频理解或真实版权判断；live每条仅一次，未测稳定成功率。没有强杀/断电恢复、长期并发、大规模性能、企业身份鉴权或真实发布。没有整批最优排期、通用撤回或自然语言入口。

优先补多轮独立live样本和更丰富风险资料，继续核对工具观察、恢复动作及调用成本；若接外部审核，先约定素材版本绑定和异步报告，避免在写事务等待网络。正式题号仍待核实，实际人工用时缺少独立计时。用户随后明确授权提交推送；原22次历史已推送到公开仓库，本轮交付修正随新提交上传，最终远程SHA在操作完成后核对。

## 分享审核后的改进与限制

前次360项覆盖既定契约，没有覆盖最低可审核资料、过去时间、跨请求发布意图和未保存建议。新增32项后392项通过；迁移旧用例时保留审核失效和容量断言，仅补齐合成媒体字段或声明显式再次发布，避免通过放松断言掩盖问题。

新8条live中，最低资料空曾提前结束，保存失败曾错用block；程序拒绝后模型纠正。说明可信结束校验重要，也说明样本不能当作模型首答可靠率。后续本人试用应重点核对缺项提示、重复拦截、回放标记及失败提议是否易读。该试用尚未完成。此前约4–5小时只估算原47轮交互执行，本次新增阶段另计；未精确记录人工净时长，不据AI自动执行时长反推个人工时。

## 当前任务工作流的学习与限制

最重要的修正是先核实真实业务身份：用户明确同素材不会在同账号反复发送，因此“允许显式再次发布并处理两份有效草稿”增加了错误复杂度。当前用一个稳定任务承载资料和要求变化，内部请求继续不可变；重复提交与用户修改有明确区别。

最难的工程问题是替换期间同时保住旧方案和确认边界。新要求未保存成功时保留旧有效草稿及历史，但不给出可交接；成功时原子替换，重新计算确认。历史批准回执和当前方案有效性分别展示，解决“过去成功等于现在仍有效”的错误。工作入口复用现有模型工具循环，避免把产品菜单实现成替代模型决策的固定流程。

验证方面，418项均有通过记录，但整套执行遇到Windows本机socket初始化失败，不能写成一次全量无失败；原失败和定向复核均归档。8条新live中的保存失败仍出现一次错误结束动作，经程序拒绝后纠正。下一步应由本人实际走一遍补资料、冲突确认、修改失败及交接流程，再决定提示和操作是否足够易懂；该独立试用尚未发生。还需在允许本机回环的环境复验单进程整套、多次独立live、长期并发和断电恢复。本轮没有增加这些未经验证的能力声明。

建议三小时是题目建议投入，本项目已持续迭代，不能声明按三小时完成。旧约4–5小时粗估只涵盖先前47轮交互执行；本次设计、编码、测试和模型等待另计，没有以自动执行时间推算人工净工时。

## 本轮体验与验证复盘

补M02让已确认M01失效，暴露的是全局修订被误当成每项业务依赖变化。改为用有效素材、规则和选定时段核对持久化方案，保留历史证据版本；运行中的全局并发防线仍存在。连续工具循环证明未变方案重查仍reused/confirmed，避免只验证数据库状态而遗漏结束条件。

隐藏复杂度的重点是本机时间与明确问题：UTC和IANA保留在工程契约中，普通交互用本地日期与偏移；版权等信息必须由用户明确回答。CSV解决直接阅读，内容版本和静态提醒解决本人试用的可追溯性，没有扩展成协同发布系统。

验证不能靠调整表述解决环境失败。两套新安装环境的源码一致，但此前三次完整438项执行仍有本机socket初始化失败；未跳过测试或改造事件循环以求通过。随后获授权完成独立CI及最新本地复验，见下节。当前仍没有独立人工试用证据。新增阶段不计入旧4–5小时粗估，人工净用时未知。

## 独立复验的实际收获

用户授权推送后，本地全新安装和GitHub独立Windows环境均完整438项通过，同一业务源码没有为了求绿改断言、跳过测试或换事件循环。原失败与后续完整通过必须同时保留：新结果证明本次运行成功，不能证明Windows权限问题永不再现。工作流提交权限与Actions触发权限也须分别核实，不能把推送成功当成CI已启动。

按题目重新执行28条场景及8条真实模型路径，确认时段冲突后重查、硬要求待确认、防重复和失败不虚报均成立。保存失败时模型仍有一次错误结束动作被拒绝，说明程序边界仍必要，不能把终态正确当成模型每步正确。下一步优先由本人按真实使用顺序试用补资料、改期、取消和CSV，再决定是否值得接真实团队资料表；不为考核演示补建多人协作系统。
